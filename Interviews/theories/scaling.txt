 ** Monitor a Node.js Application in Production
 Key Metrics to Monitor
When monitoring a Node.js application, focus on the following metrics:

    1. CPU and Memory Usage
    Excessive CPU or memory consumption can signal inefficient code or memory leaks.

    2. Request and Response Times
    Measure how quickly your application processes incoming requests.

    3. Error Rates
    Track application errors (5xx status codes) and uncaught exceptions to ensure stability.

    4. Throughput
    Monitor the number of requests handled per second to understand your app’s workload.

    5. Garbage Collection
    Analyze garbage collection activity to spot potential memory management issues.

    6. Database Performance
    Query times and connection pool usage can significantly affect your app’s performance.

1. Structuring Your Project for Maintainability
    Proper project structure is crucial for creating a scalable and maintainable application. 
    A well-organized codebase makes it easier for developers to understand and extend functionality 
    as the application grows.

    Folder Structure
    A common way to structure a Node.js application is using the MVC pattern (Model-View-Controller). 
    Here's an example:

    my-app/
    ├── controllers/
    │   └── userController.js
    ├── models/
    │   └── userModel.js
    ├── routes/
    │   └── userRoutes.js
    ├── services/
    │   └── emailService.js
    ├── middlewares/
    │   └── authMiddleware.js
    ├── config/
    │   └── dbConfig.js
    ├── app.js
    └── package.json
    Explanation
    This structure separates different responsibilities, making the application modular and easier 
    to scale. Controllers handle the logic, models manage data, routes define endpoints, 
    services encapsulate reusable logic, and middlewares handle tasks like authentication.

✔ Keep dependencies updated (npm audit)
✔ Use environment variables (dotenv)
